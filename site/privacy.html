Privacy

The online demo · last updated 17 November 2026

This notice covers the demo on this website, which scores one photo at a time on a server we run. Tintype itself runs on your own computer and sends nothing anywhere; this notice is only about the demo.

Who runs the demo

The Tintype maintainers, as a free, non-commercial open-source project. Contact us through GitHub issues.

What happens to your photo

  • When you choose a photo, your browser sends the original file over an encrypted (HTTPS) connection to our server on Google Cloud Run in the United States (region us-central1, Iowa).
  • The server reads the photo into memory, scores it, sends back the result and discards the photo. It is never written to disk, stored, shared, or used to train or improve any model.
  • The result (a verdict and a score) is sent to your browser and not kept on the server.
  • Your browser does not send the file's name: the page replaces it with the word "photo".
  • Metadata inside the file, such as the camera model, the date or a location, travels with the photo, because the demo needs the original file. The server does not record or keep it. If you would rather not send it, remove it before uploading, or install Tintype and run it locally.

Your network address

  • Your IP address reaches our server because that is how the response gets back to you. The server also uses it to enforce the demo's limits.
  • When you open the photo picker, or drag a file over it, the page also sends an empty request that wakes the server, so that a photo you then choose is scored sooner. That request carries no photo and nothing else about you, counts toward no limit and is not recorded, but your address reaches the server with it even if you choose nothing.
  • For that, it keeps a keyed hash of the address (for IPv6, of its first 64 bits), not the address itself. The key is random, made when the server starts and never stored, so once the server stops, nobody can match the hash to an address.
  • The hash is held only in memory. Once a new UTC day starts (and your 10-minute window, if it runs past midnight, has ended), the hash is dropped the next time the server runs. Everything it holds is lost when the server stops, which it does by itself within about 15 minutes of its last visitor.
  • The server does not write your address, your browser's details, the photo, its contents, its metadata or any fingerprint of it to its logs. Its only log line about the demo is an hourly count of photos scored and requests refused.

Google, as our host

  • Google Cloud runs the server. Google's network receives your connection first, decrypts it and passes the request on, so Google handles your IP address and the request on our behalf, under its own Cloud Data Processing Addendum and privacy notice.
  • By default Cloud Run writes a log entry for every request, including the caller's IP address and browser. We have set our project to discard those entries for the demo instead of storing them.
  • We cannot see or control what Google's own systems do with traffic in passing, for example to protect its network from abuse.

This website

GitHub Pages hosts this website, and GitHub may log visits for security under the GitHub privacy statement. The site uses no cookies, analytics, advertising, third-party scripts or web fonts, and the demo stores nothing in your browser.

Your choices

Because the demo keeps no photos, results or addresses, there is nothing for us to look up, export or delete afterwards. If you have a question, open an issue on GitHub. To check photos without sending them anywhere, install Tintype.

Changes

If the demo changes how it handles data, this page will change first, with a new date at the top. Its history is public in the project repository.
